# /explain — объяснение для человека

Агенты делают всё больше работы сами. Человек всё больше проверяет и понимает
(A. Karpathy). Схему понять легче, чем текст. Интерактивную страницу — легче, чем
схему. Страница одноразовая: она нужна для понимания сейчас, а не для архива.

## Цель

`/explain <цель>`. Цель — одно из:

- ветка или MR: `worktree-61-agent-rules`, `!245`;
- модуль: `src/domain/advice`;
- тема: «как ассистент проверяет ответ модели».

Цели нет — объясни текущую ветку.

## Шаги

1. Собери факты командами. Не пересказывай по памяти.
   - Ветка: `git log --oneline origin/main..<ветка>`,
     `git diff --stat origin/main...<ветка>`, затем главные места diff.
   - MR: `bash scripts/gitlab-mr.sh show <iid>`, затем как ветка.
   - Модуль: публичный `index.ts`, README модуля, кто его импортирует (`grep -rl`).
   - Тема: найди код, который это делает. Запиши места как `файл:строка`.
2. Напиши одну HTML-страницу: `<scratchpad>/explain-<цель>.html`. Один файл, без
   сборки.
3. Покажи страницу. Есть инструмент Artifact — опубликуй её (страница приватная по
   умолчанию). Инструмента нет — дай путь к файлу.
4. Не добавляй страницу в git.

## Страница

Блоки по порядку:

1. **Суть** — 3–7 предложений на ~80% STE (`CLAUDE.md`, «Как писать»). Что изменилось
   для пользователя или для кода.
2. **Схема** — модули и поток данных цели. Изменённое подсвечено. Inline SVG или
   mermaid.
3. **Было → стало** — поведение, числа, файлы.
4. **Проверено** — команды и их результат. Не запускал — так и напиши.
5. **Риски и не сделано** — список. Рисков нет — «нет известных».
6. **Где смотреть** — список `файл:строка`.

Правила:

- Только факты из шага 1. Нет факта — `TBD`.
- Интерактив — только если он помогает понять: раскрыть кусок diff, переключить
  «было / стало», навести на узел схемы.
- Светлая и тёмная тема. На ширине телефона нет горизонтальной прокрутки.
- Внешние скрипты — только с `cdnjs.cloudflare.com` или `cdn.jsdelivr.net`. Лучше без
  них.
- На странице нет секретов, ключей и содержимого `.env`.
