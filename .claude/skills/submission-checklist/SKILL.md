# Чек-лист сдачи

Источник — разделы «Технические ограничения», «Критерии оценки» и «Что сдаётся» в
`task.md`. Каждый пункт проверяется **командой или файлом**, а не памятью. Результат —
таблица `пункт | ✅/❌/⚠️ | доказательство | что сделать`. Ничего не исправлять молча:
сначала отчёт, исправления — отдельными коммитами в ветке через MR.

## 0. Состояние git

```bash
git fetch --prune && git status -sb              # чисто, не behind
git log --oneline origin/main -1                 # commit сдачи — в origin/main, не только в ветке
git ls-remote origin main
```

Открытые MR с нужной для сдачи работой — ❌: в `main` их нет.

## 1. Работающий сервис

- Адрес сервиса и сведения для доступа есть в README.
- Адрес открывается **с другой машины / другой сети**, не только с localhost.
- Сценарий проверяющего пройден **сегодня** на commit сдачи: открыть редактор →
  загрузить демо-проект → внести изменение → сохранить → повторно открыть. Нет записи о
  прогоне — ⚠️, а не ✅.
- Ассистент отвечает на задеплоенном сервисе (ключ API задан на сервере) и
  деградирует без LLM с пометкой, если API недоступен.

- [ ] пошаговый сценарий проверки: открыть, загрузить демо, изменить, повторно открыть

## 3. Демо-проект — один ZIP

```bash
unzip -l <архив>.zip
```

- [ ] исходный вариант плана (редактируемые данные, не только картинка)
- [ ] изменённый вариант плана
- [ ] рекомендация ассистента
- [ ] описание её эффекта: что изменили, почему, как изменились планировка и показатели
- [ ] инструкция повторного открытия
- [ ] **оба плана открываются в задеплоенном редакторе** с зонами, оборудованием, `id`,
      атрибутами — проверить загрузкой из распакованного архива, а не из рабочей копии
- [ ] план своего условного отделения, не `example_plan.json` и не реальный план

## 4. Зависимости

Lock-файл (`package-lock.json` / `pnpm-lock.yaml` / `uv.lock` / `requirements.txt` с
версиями) закоммичен и соответствует манифесту. Чистый клон запускается по README:

```bash
git clone <origin> /tmp/check && cd /tmp/check   # затем команды из README
```

## 5. Секреты и LLM

```bash
bash .claude/hooks/check-secrets.sh              # пустой вывод = чисто
git log -p | grep -i -E 'api[_-]?key|secret|token|sk-' | head   # не утекало ли в истории
grep -r -i -E 'openai\.com|anthropic|claude|gemini' --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=.claude . | head
```

- `.env.example` — только плейсхолдеры. Ключ, найденный в истории, — ❌ с пометкой:
  ключ нужно перевыпустить, удаление файла его не отзывает.
- Используемая модель — Qwen, DeepSeek, GigaChat или YandexGPT (ограничение организаторов, ответ 16.09). Библиотека с
  OpenAI-совместимым клиентом допустима, если запросы идут к разрешённому провайдеру.
