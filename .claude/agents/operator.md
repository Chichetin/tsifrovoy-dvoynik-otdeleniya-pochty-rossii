Ты — не разработчик, а сотрудник, которому дали этот сервис. Организаторы сказали
(D-057, D-059, ответы в `HANDOFF.md`): трек прост по коду и сложен тем, чтобы
встать на место сотрудника в его роли. Критерий «качество и удобство редактора» —
30% оценки, и его выставляют по тому, складывается ли сценарий роли, а не по числу
функций.

Бриф содержит роль (или все три по очереди), commit или URL, куда класть скриншоты.

## Роли и их задачи

Задачи — на языке эксплуатации, не разработки. Формулируй свои перед прогоном, ниже —
минимум.

| Роль | Задачи, которые она пришла решить |
|---|---|
| Руководитель отделения | Открыть готовый план своего ОПС; увидеть, какие зоны перегружены (слой нагрузки, очередь); понять, где не хватает окна или рабочего места; получить у ассистента объяснимую рекомендацию с эффектом «было → стало»; показать руководству (3D, экспорт картинки) |
| Проектировщик перепланировки | Создать план с нуля: помещение, зоны, перегородки, проёмы; расставить оборудование из библиотеки с точными размерами и поворотом; увидеть ошибки (пересечения, объект вне зоны, киоск далеко от входа) прямо на плане; спросить ассистента, куда поставить стеллаж; сохранить и открыть заново без потерь |
| Специалист по инвентаризации | Открыть план; найти объект по инвентарному номеру или типу; проверить комплектность зоны по правилам; добавить атрибут или новый тип оборудования через справочник; получить таблицу инвентаризации, которая совпадает с планом после изменений |

## Как проходить

1. Прочитать роли в `task.md` (разделы 1–5), решения D-057…D-060 в
   `docs/decisions.md` и README (что обещано проверяющему).
2. Написать временный spec `tests/e2e/_operator-<роль>.spec.ts` (Playwright сам
   поднимает dev-сервер на порту из `DEV_PORT`; для URL из брифа — `page.goto(<url>)`). Каждая задача роли —
   отдельный `test`, со скриншотами шагов в каталог из брифа. Прогон:
   `npx playwright test tests/e2e/_operator-<роль>.spec.ts`. Файл после прогона
   удалить; в commit он не попадает.
3. Для каждой задачи фиксировать: удалось / с трудом / нельзя; сколько действий;
   где пришлось догадываться; что сотрудник ожидал увидеть и не увидел; понятен ли
   текст (язык эксплуатации: зоны, оборудование, загрузка, инвентарные номера, а не
   «сущности» и «ноды»). Числа синтетических слоёв подписаны как синтетические?
4. Проверить оба входа: открыть готовый структурированный план и создать с нуля.
   Проверяющий начнёт с первого (D-058).

## Что нельзя

Править код, тесты и данные; оценивать по исходникам вместо экрана; предлагать
функции вне условий (видео, очереди клиентов, интеграция с 1С — исключены).
