# src/features/onboarding

Мини-обучение при первом входе: четыре шага по сценарию проверяющего с подсветкой
настоящих панелей.

**Владелец:** поток 2. **Пакет:** UX-очередь №2 (`HANDOFF.md`), решение D-193.

## Что внутри

- `tour.ts` — без DOM: шаги (`TOUR_STEPS`: открыть → изменить → проверить и спросить
  ассистента → сохранить и открыть заново), отметка «обучение пройдено» в
  `localStorage` под ключом `ops-twin.onboarding.v1` (`shouldShowTour`,
  `rememberTour`, каждый вызов хранилища в `try/catch`), место карточки у
  подсвеченной панели (`placeCard`).
- `anchor.ts` — рамка панели, помеченной приложением атрибутом `data-tour`; у
  обёртки `display: contents` берётся первый видимый дочерний элемент.
- `Onboarding.tsx` — окно: `role="dialog"`, `aria-modal`, фокус на карточке,
  «Пропустить» на каждом шаге, «Назад», «Далее», «Готово» на последнем; Esc —
  пропустить. Пока окно открыто, затенение забирает мышь, а клавиши не доходят до
  редактора.

## Граница модуля

Не импортирует соседние модули и store. Панели находит только по `data-tour`,
который ставит `src/app/App.tsx` (`files`, `tools`, `side-left`, `side-right`);
нет панели на экране — шаг показывается без подсветки. Открывать ли окно, решает
приложение (`shouldShowTour`), итог возвращается через `onClose`. В файл плана
ничего не пишет.

## Проверки

- `tour.test.ts`, `Onboarding.test.tsx` — unit.
- `tests/e2e/onboarding.spec.ts` — браузер: кольца вокруг настоящих панелей, отметка
  в `localStorage`, файл плана с обучением и без него побайтно одинаков, работа без
  `localStorage`. Остальные спеки открывают приложение через фикстуру
  `tests/e2e/fixtures.ts`, которая отмечает обучение пройденным заранее.
