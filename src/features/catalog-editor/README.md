# src/features/catalog-editor

Панель «Справочник»: типы оборудования, типы зон, их атрибуты и правила комплектования
правятся из интерфейса, без правки JSON (D-139, D-150).

**Владелец:** поток 3.

## Граница модуля

`catalog-edit.ts` — чистые функции над `Catalog`: собирают новый каталог, ничего не
применяют. Применяет одна команда `catalog.replace`, и она же отказывает: тип, которым
пользуется объект или зона; обязательный атрибут без умолчания; дубли и битые ссылки. Панель
показывает отказ у себя. Ни стора, ни документа модуль не хранит.

## Файлы

- `catalog-edit.ts` — добавить/удалить тип оборудования, тип зоны, атрибут (у любого из
  них), правило; `slugId` — читаемый идентификатор из подписи; `layersReading` — какие
  слои читают атрибут.
- `CatalogPanel.tsx` — формы и списки; каждое действие — `catalog.replace`. Каждая группа
  (типы оборудования, типы зон, атрибуты выбранного типа, правила) — свой блок с общим
  классом `.panel__group` (см. `src/app/styles.css`), тот же приём, что и в
  «Инвентаризации». Списки типов оборудования, типов зон и правил свёрнуты по умолчанию —
  видны первые три записи, «Показать все (N)»/«Свернуть» раскрывает и сворачивает обратно
  (`aria-expanded`, `aria-controls`); строки скрыты атрибутом `hidden`, а не удалены из
  DOM. Кнопки нет, если записей не больше трёх. Добавление нового типа или правила сразу
  раскрывает его список — форма добавления никогда не сворачивается сама.

**Проверки:** `catalog-edit.test.ts` (сквозь `applyCommand`), `CatalogPanel.test.tsx`
(сворачивание списков, разделение групп), `tests/e2e/catalog-editor.spec.ts`.
