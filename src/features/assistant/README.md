# src/features/assistant

Запрос сценария, карточки рекомендаций, before/after, preview и fallback.

**Владелец:** поток 4. **Пакеты:** A06.

## Граница модуля

Потребляет contracts и domain/advice для локального fallback; fetch только к своему /api/advice. Ключи и прямые вызовы провайдера запрещены.
Серверный 429 ограничивает вызовы модели, но не лишает пользователя расчёта:
`advice-client.ts` пересчитывает рекомендации в браузере и явно помечает режим
«Без LLM». Ошибки 400/422 остаются ошибками плана или запроса.
В «Комплектовании» панель показывает название типа оборудования и зоны из
справочника текущего плана рядом с проверенными числами рекомендации.
В «Найти место» у каждого варианта названа его зона — имя из плана
(`data-testid="candidate-zone"`), либо «вне зон» (D-186); голого `id` в подписи нет.
У «Ссылок» и «Изменений» карточки подпись и `title` кнопки — имя сущности
(`title="Показать на плане · id <id>"`), а `id` ещё и виден без DevTools: под ними —
раскрытие «ID зон и объектов» со списком `<code>id</code> — имя» на все `refs` и
`changes.ref` рекомендации (D-320/D-322/D-323, #10, объяснимость — CLAUDE.md «ИИ-ассистент»).
В чате (`AgentChat.tsx`) id зоны или объекта, который код вписал в ответ, браузер сам
превращает в кнопку с именем сущности (тот же `title`), а под ответом — то же
раскрытие «ID зон и объектов» по `answer.refs` — для клавиатуры и без клика по каждому
упоминанию в тексте. Id типа или правила (не зона и не объект) на кнопку не
переводится — предложение остаётся как его написал расчёт, id в тексте виден (review
!318): такую фразу сокращает только `hideNamedIds` (D-321) — там, где у текста нет
своего клика по каждому упоминанию (например, «Ограничения» карточки).
Необязательное пожелание пользователя (D-222) модель использует только для выбора
среди уже рассчитанных кодов причины и вариантов. Оно не расширяет расчёт и не может
добавить число или факт; без LLM панель прямо пишет, что пожелание не учитывалось.
Запрос чата (`agent-client.ts`) всегда заканчивается результатом (#137). «Остановить» и
«Новый диалог» вызывают `stopAgent()`. Через 65 с (`LLM_TIMEOUT_MS` сервиса + 5 с)
запрос прерывает таймаут страницы. В обоих случаях ответ собирает расчёт в браузере
с пометкой «Без LLM» и причиной: «Запрос остановлен» или «Сервер ассистента не ответил».
