# src/features/validation

Список нарушений, повторная проверка, подсветка и переход к проблеме.

**Владелец:** поток 3. **Пакеты:** V02.
Реализовано пакетом V02: список находок `validatePlan`, ошибки выше предупреждений, переход к объекту по `id`. В обычном режиме находка показывает сообщение, понятное название объекта, зоны или слоя и источник правила; код, `kind:id`, `ruleId` и путь раскрываются общим флажком «Показать технические детали» (D-224). Неизвестный `id` остаётся видимым как единственное доступное имя (D-124). `IssueLayer.tsx` без клика ставит маркер с числом находок и цветом серьёзности у каждой сущности, которую находка называет первой, а полигоны находок выделенной сущности заливает и обводит сплошным контуром с белой каймой; отбор — `issue-highlight.ts` (`highlightsFor`, `issueMarkers`, `markerAnchor`; D-117, D-157). Маркеры — узлы Konva `name="issue-marker"`, e2e `tests/e2e/issues-on-plan.spec.ts` читает их через `window.Konva`.

## Граница модуля

Получает `ValidationIssue[]` через props — локальное расширение `Issue` с необязательными `ruleIds`, которое не меняет общий контракт и формат плана. Для рисования использует geometry, диагностику не пересчитывает в JSX.

## Файлы по плану

Следующие файлы создаются при реализации соответствующих пакетов:

- `ValidationPanel.tsx` — V02.
- `IssueOverlay.tsx` — V02.

Имена находок панель берёт из `planIndex(plan).nameOf(ref)` (`src/domain/plan-index`, D-202); своего `naming.ts` у модуля больше нет.

**Проверки:** `ValidationPanel.test.tsx` (Vitest): понятные названия без технического шума по умолчанию, раскрытие кода/ссылок/правила/пути, неизвестный `id`, переход и порядок «ошибки раньше предупреждений»; `validation.test.ts` отделяет источник правила от его технического `id`; `tests/e2e/issue-highlight.spec.ts` проверяет оба режима и переход на план.
