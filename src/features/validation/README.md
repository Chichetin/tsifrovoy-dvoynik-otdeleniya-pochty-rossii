# src/features/validation

Список нарушений, повторная проверка, подсветка и переход к проблеме.

**Владелец:** поток 3. **Пакеты:** V02.
Реализовано пакетом V02: список находок `validatePlan`, ошибки выше предупреждений, переход к объекту по `id`. В обычном режиме находка показывает сообщение, понятное название объекта, зоны или слоя, обозначение стены/проёма и источник правила; сообщения диагностики связей также используют подписи объектов и названия зон. Код, `kind:id`, `ruleId` и путь раскрываются общим флажком «Показать технические детали» (D-235). Неизвестный `id` остаётся видимым как единственное доступное имя (D-124). `IssueLayer.tsx` без клика ставит маркер с числом находок и цветом серьёзности у каждой сущности, которую находка называет первой, а полигоны находок выделенной сущности заливает и обводит сплошным контуром с белой каймой; отбор — `issue-highlight.ts` (`highlightsFor`, `issueMarkers`, `markerAnchor`; D-117, D-157). Маркеры — узлы Konva `name="issue-marker"`, e2e `tests/e2e/issues-on-plan.spec.ts` читает их через `window.Konva`.

Клик по кружочку маркера открывает список развёрнутым и ведёт к находкам этой сущности (D-263): `IssueLayer` принимает необязательный `onMarkerClick` (свой тип, не общий контракт) — слой и маркер ловят мышь только когда он передан (в «Выбор»/«Обзор»; во время рисования не передаётся, и клик проходит инструменту насквозь), маркер останавливает всплытие (`cancelBubble`), чтобы не выбрать и не потянуть объект под собой. `ValidationPanel.tsx` принимает необязательный `focus?: FocusRequest` (тоже локальное расширение контракта) — при новом `sequence` прокручивает к первой находке этой сущности (`scrollIntoView`) и красит её строки классом `is-focused` с `aria-current="true"`.

## Граница модуля

Получает `ValidationIssue[]` через props — локальное расширение `Issue` с необязательными `ruleIds`, которое не меняет общий контракт и формат плана. Для рисования использует geometry, диагностику не пересчитывает в JSX.
