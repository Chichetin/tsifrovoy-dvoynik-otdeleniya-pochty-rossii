# src/features/inventory

Границы колонок в перечне объектов, разрезе по зонам и таблице площадей можно тянуть мышью или двигать стрелками с клавиатуры (D-213). `resizable-columns.tsx` хранит отдельную процентную раскладку каждой таблицы в `localStorage`, не даёт соседней колонке стать уже 10% и возвращает исходные ширины двойным щелчком; повреждённые сохранённые значения безопасно игнорируются.

Таблица оборудования, фильтры, площади и переход к объекту.

**Владелец:** поток 3. **Пакеты:** M02.
Реализовано пакетом M02: сводка «объекты по типам» (D-121), поиск и фильтр по перечню (D-123), таблица объектов и разрез по зонам из `buildInventory`, переход к объекту и зоне по клику. Названия типов и зон берутся из открытого документа, сырой `id` стоит рядом вторичным текстом (D-122). Формул в разметке нет: числа приходят из `buildInventory`, `rows.ts` их только группирует, называет и фильтрует. `MetricsPanel.tsx` показывает площади помещения и зон из `measurePlan`; формул в разметке нет.

Перечень как рабочий инструмент инвентаризации: колонка «Инв. №» из атрибута `inventoryNumber` открытого документа, объект без номера подписан «—» (D-159); сортировка по любой колонке тремя кликами — по возрастанию, по убыванию, обратно к порядку плана; таблица прокручивается внутри панели (D-141); фильтр и сортировка сбрасываются при смене документа и когда выбранного типа в плане не осталось (D-140).

Обе группы — «Объекты по типам» и перечень объектов — свёрнуты по умолчанию: видны первые три, «Показать все (N)»/«Свернуть» раскрывает и сворачивает обратно (`aria-expanded`, `aria-controls`). Строки не удаляются из DOM — скрыты атрибутом `hidden`, поэтому число строк в разметке не меняется, меняется только видимость. Кнопки нет, если элементов не больше трёх. Активный поиск или фильтр по типу показывает все совпадения без кнопки — свёрнутый экран не должен прятать находку. Строка, по которой кликнули в перечне, остаётся видимой и после повторного «Свернуть» — иначе выбор в перечне расходится с тем, что видно на экране; у панели нет прав на состояние выбора вне неё самой (контракт `InventoryPanelProps` не передаёт его), так что подсветка строки по клику на плане или переходу из «Проверки» этим не покрыта — это её прямая граница, а не пропуск.

Выгрузка: кнопка «Скачать CSV» отдаёт то, что показано, — с учётом фильтра и порядка сортировки, о чём подпись рядом с кнопкой сообщает до клика. Формат — `;` как разделитель, UTF-8 с BOM, CRLF, колонки как в таблице плюс `id` объекта, типа и зоны (D-160). Файл собирают чистые `inventoryCsv` и `toCsv` из `rows.ts` (экранирование по RFC 4180), а кнопка показывает загрузку, результат и ошибку.

## Граница модуля

Получает Inventory и Result<Metrics> через props. Формулы в domain; выбор/фокус через callbacks. Названия — из `document` в пропсах, который передаёт композиция приложения; без него панель работает и показывает `id` (D-124). Состояние фильтра живёт в компоненте и документ не меняет.

## Файлы по плану

Следующие файлы создаются при реализации соответствующих пакетов:

- `InventoryPanel.tsx` — M02.
- `rows.ts` — M02: чистые функции строк, сводок, фильтра, сортировки и CSV, без React; названия типов и зон — из `planIndex` (`src/domain/plan-index`, D-202).
- `MetricsPanel.tsx` — M02; числа через `domain/number-format`, единица в подписи таблицы зон (D-197). Строки зон идут в порядке вложенности: вложенная сразу под родителем, с отступом, значком ветки и именем родителя в `aria-label` (D-239) — таблица остаётся плоской, по строке на зону.
- `zone-tree.ts` — чистый порядок строк по `parentId`: обход дерева с глубиной, соседи в порядке плана. Ссылка на несуществующего родителя и цикл дают верхний уровень — ни одна зона не теряется и обход не зацикливается; о самом дефекте говорит «Проверка». `zone-tree.test.ts` — 8 проверок.
- `MetricsPanel.test.tsx` — запись площадей по-русски и числовые колонки.

**Проверки:** `rows.test.ts` и `InventoryPanel.test.tsx` (Vitest), `tests/e2e/inventory.spec.ts` в браузере — сводка против строк, фильтр, правка в 2D и объём 1000 объектов; после подключения — общий Q01.
