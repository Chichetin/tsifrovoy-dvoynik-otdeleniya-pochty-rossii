# src/features/layers

Панель слоёв: CRUD, видимость, блокировка, порядок и перенос содержимого;
информационные слои поверх плана с легендой из справочника.

**Владелец:** поток 2. **Пакеты:** U05, U05-ux (D-162).

## Граница модуля

Потребляет contracts. Изменения идут через Command; скрытие не меняет инвентаризацию.
Информационный слой документ не меняет: он читает атрибуты зон и объектов, а
цвета, единицы и порог шкалы берёт из `catalog.layerTypes`.

## Файлы

- `LayersPanel.tsx` — список слоёв: имя, строка «Показывать» с SVG-значками замка, порядка и удаления, короткая строка со счётом содержимого у обычного слоя (у информационного её нет — легенда и свёрнутое «Что показывает слой» уже говорят, что он рисует), свёрнутое «Что показывает слой», легенда и таблица значений (D-197, D-266).
- `InformationLayer.tsx` — рисование информационных слоёв на холсте Konva, легенда холста.
  Сектор обзора камеры и плашка подписи значения рисуются без буферного холста
  (`perfectDrawEnabled: false`, D-190); `InformationLayer.test.tsx` — 2 проверки на демо-плане:
  ни одна фигура слоя не идёт через буфер, и случай, ради которого буфер существует, в слое есть;
  плюс регрессия D-241 — реальный рендер на всём демо-плане, ни один `info-label` не пересекает
  `zoneNameBox` (тоже экспортирован — тест считает по функции компонента, а не по своей копии
  формулы), мутацией подтверждено, что откат к старому `labelAnchor`/`y + 8` тест роняет.
  Препятствие для собственных подписей строится по реальному положению имени зоны
  (`zoneNameAnchor`, D-241) — значение слоя («45 %» и подобные) не садится на подпись зоны,
  сдвинутую правилом D-216 из-за объекта в её обычном месте.
- `zone-name-anchor.ts` — якорь имени зоны, которым `InformationLayer` защищает своё место
  от наложения: намеренная копия `zoneLabelAnchor` из `src/features/plan-tools/zone-label.ts`
  (D-216), потому что фичи не импортируют друг друга (`eslint.config.js`), а контракт
  `InformationLayerProps` в пакете D-241 менять было нельзя. Синхронизацию с оригиналом
  проверяет `tests/zone-name-anchor-sync.test.ts` (корень `tests/`, не `src/features/**` и не
  `tests/e2e/`: чисто вычислительная проверка, входит в обычный `npm test`) — оба демо-плана
  плюс четыре синтетических случая на граничные ветки правила; своя мутационная проверка самой
  копии — 5/5 убито, `zone-name-anchor.test.ts`. Тот же файл сверяет и три константы шрифта,
  ширины колонки и `letterSpacing` в `InformationLayer.zoneNameBox` — оракул импортирует их из
  `ZoneNameLayer.tsx` (экспортированы оттуда же ради этого сторожа), а не хранит вторую копию чисел.
- `LayersPanel.tsx` также рисует под первым обычным слоем («Основной») подпункты «Напольные объекты (N)» и «Потолочные объекты (N)» со своими флажками (D-275): правило деления — `src/domain/object-mount.ts` (низ объекта ≥ 2,0 м — потолочный), состояние скрытия держит `App` и в план не пишет; панель получает его необязательным пропом `objectMounts` сверх контракта `LayersPanelProps`. Сектор обзора камеры рисует информационный слой «Камеры и зоны обзора» по настоящему документу, поэтому при скрытых потолочных объектах сектор остаётся на плане — сознательно: группы касаются только содержимого «Основного», информационные слои живут своими флажками. Объект, поставленный из библиотеки в скрытую группу, снова показывает эту группу.
- `legend.ts` — легенда слоя из справочника (шкала, порог, цвет, единица).
- `label-layout.ts` — раскладка подписей без наложения.
- `heat-regions.ts` — какая зона красит какую часть плана при вложенности (D-136).

**Проверки:** собственный browser harness в `tests/harness/<ID>.tsx`, spec в `tests/e2e/`; после подключения — общий Q01.
