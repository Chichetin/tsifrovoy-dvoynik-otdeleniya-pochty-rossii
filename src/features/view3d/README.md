# src/features/view3d

Производная сцена Three.js и её показ с общей selection.

**Владелец:** поток 3. **Пакеты:** D01 (сделан).

## Граница модуля

Потребляет contracts и `src/domain/geometry` (публичный `index.ts`), получает
`PlanDocument` и `selection` через `View3DProps`. Хранит только состояние камеры и
ресурсы сцены, не второй редактируемый план: сцена строится заново из документа при
каждом его изменении (D-080, D-083).

## Файлы

- `scene.ts` — `buildScene(plan, catalog = plan.catalog)`: чистая функция, без
  Three.js. Результат — список призм `{ kind, ref, polygon, base_m, height_m, color,
  opacity }`: пол по `room.boundary`, зоны цветом типа из справочника (вложенные —
  на слой выше), стены по `thickness_m`/`height_m` с настоящими дырами проёмов
  (полосы по высоте через `wallObstacles`, D-082), проёмы — полупрозрачные плоскости,
  объекты — `footprint` из geometry (тот же поворот, что в 2D, D-010/D-081).
  `isSelected(prism, selection)` — сравнение по `kind` и `id`. Объекты и зоны скрытых слоёв
  (и с несуществующим `layerId`) в сцену не попадают — как на холсте 2D; помещение, стены и
  проёмы слоёв не имеют и видны всегда (D-106).
- `webgl.ts` — `probeWebgl()` и `hasWebgl()`: проба создаёт контекст, сразу отдаёт его
  через `WEBGL_lose_context` и запоминает ответ на сессию, поэтому переключение «2D / 3D»
  больше не расходует контексты браузера (D-107).
- `View3D.tsx` — публичный компонент по `View3DProps`: проверяет WebGL, лениво
  грузит `View3DCanvas` (отдельный чанк с three) и показывает только сцену — без
  боковой колонки со списком примитивов (D-263, отменяет D-257): управление понятно
  без неё, а выбор и карточка «Свойства» остаются общими с 2D. Состав сцены остаётся
  машиночитаемым: секция несёт `data-zones-count` / `data-objects-count` /
  `data-walls-count`, посчитанные по призмам, а не по документу — скрытый слой меняет
  числа. Состояния: загрузка модуля, сцена, ошибка (`LoadFailure`,
  `data-testid="view3d-error"`), нет WebGL (`data-testid="view3d-unavailable"`).
- `View3DCanvas.tsx` — Three.js: `ExtrudeGeometry` по полигону призмы, оси модели
  без преобразования (X, Y — план, Z — высота, `camera.up = +Z`), `OrbitControls`,
  кадр по описанной сфере помещения, рендер по требованию (без цикла анимации),
  `dispose` геометрий, материалов, контролов и рендерера при размонтировании. Потеря
  контекста (`webglcontextlost`) показывает сообщение `data-testid="view3d-context-lost"`
  вместо чёрного холста и освобождает рендерер, `webglcontextrestored` собирает сцену
  заново из текущего плана (D-107).

## Проверки

- `npm test -- src/features/view3d/scene.test.ts` — 20 тестов: поворот 37° совпадает с
  `footprint`, сдвиг объекта сдвигает призму, цвет зоны и объекта из справочника,
  переопределение справочника аргументом, вложенность зон, пол/потолок/границы,
  дыра двери и стена над перемычкой, плоскость проёма, стена нулевой длины,
  скрытые слои (объект, зона, несуществующий слой, вложенность при скрытом родителе),
  проём на наклонной стене.
- `npm test -- src/features/view3d/webgl.test.ts` — 6 тестов пробы WebGL: контекст
  отпускается, исключение и отсутствие расширения — не падение, браузер спрашивается
  один раз за сессию.
- `npm test -- src/features/view3d/View3D.test.tsx` — 3 теста data-атрибутов секции:
  счётчики зон и объектов считаются по сцене, со скрытым слоем оба падают до нуля,
  без WebGL показывается сообщение и списка примитивов в DOM нет.
- `npm run test:e2e -- tests/e2e/view3d.spec.ts` — 7 сценариев: обычный запуск,
  SwiftShader (canvas обязан быть, выбор из инвентаризации остаётся показан после
  переключения в 3D, клик по объёму выбирает объект, пример организаторов), двадцать
  переключений «2D / 3D» подряд (контекст холста жив, `isContextLost()` — `false`),
  скрытый слой (`data-objects-count` падает до `0` и возвращается), потеря и возврат
  контекста WebGL (сообщение вместо чёрного холста, после возврата холст новый),
  выключенный WebGL (сообщение, 2D работает). Состав сцены сверяется числом
  (`data-zones-count`/`data-objects-count`/`data-walls-count` секции), а не списком —
  соответствие конкретных `id`, поворотов и цветов документу проверяет
  `scene.test.ts` на чистой функции.
- Стенд: `npm run dev` → `http://127.0.0.1:5173/tests/harness/?id=D01` (`rotated.json`,
  кнопки «сдвинуть объект» и «выбрать»).

## Известные ограничения

- Потолок не рисуется (закрыл бы интерьер); материалов, текстур и теней нет намеренно
  (5% критерия).
- Клик по объёму в 3D выбирает его тем же `onSelect`, что и 2D, инвентаризация и
  панель слоёв: одна общая `selection`, без второго состояния выбора в 3D.
- Что проба WebGL не тратит контекст на каждое переключение, проверяется только
  `webgl.test.ts`: в headless-браузере брошенные пробы освобождаются сборщиком мусора
  когда придётся, и на числе переключений это не отпечатывается.
- Сырой `example_plan.json` открывается через импорт формата организаторов
  (`src/persistence/organizer-import.ts`), а не напрямую кнопкой «Открыть»; spec
  конвертирует его сам.
