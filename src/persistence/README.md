# src/persistence

Версионированный формат, импорт примера организаторов, локальный черновик.

**Владелец:** поток 3. **Пакеты:** IO01 IO02 IO03.
`codec.ts` реализован пакетом IO01: `decodePlan`/`encodePlan` — единственная дверь между текстом файла и `PlanDocument`. Сохранение канонично (D-022) и отказывает на документе, который сам же не прочитает (D-023); нечитаемая структура и исправимая геометрия — разные исходы: пересечения и самопересечение полигона открываются для правки, битая ссылка и будущая версия — нет. `organizer-import.ts` реализован пакетом IO02: переводит `example_plan.json` в наш документ, не меняя сам пример — типы сопоставляются со справочником команды (D-025), заявленная связь объект→зона и геометрические ошибки примера сохраняются, вложенность зон восстанавливается по геометрии (D-026), а придуманные величины подписаны в `extensions` (D-027); `withTeamCatalog(plan, team)` смыкает открытый пример со справочником команды — наши типы по совпавшим `id`, типы примера остаются, правила и типы слоёв наши плюс скрытый слой на каждый тип слоя, — а версия `ORGANIZER_CATALOG_VERSION` говорит приложению, что слияние ещё не делалось (D-148). `format.ts` реализован пакетом IO03: `detectPlanFormat(text)` называет формат файла по его структуре (`schemaVersion` — наш, `ops` + `zones` + `equipment` — пример организаторов), `readPlanFile(text)` открывает файл нужной дверью и возвращает план вместе с форматом, допущениями импорта (D-086) и списком полей вне формата `dropped` — `droppedFields(payload, parsed)` сравнивает ключи файла с разобранным документом, чтобы то, что схема отбросит при сохранении, было названо при открытии (D-201). `browser-draft.ts` реализован пакетом IO03: в `localStorage` под ключом `ops-twin.draft.v1` лежит только текст `encodePlan` (D-088), запись — с дебаунсом и ленивой сериализацией, quota и недоступное хранилище возвращают причину, а не бросают (D-089); черновик читается как «нет черновика», если в нём мусор. `plan-svg.ts` — картинка плана: `renderPlanSvg(plan)` строит SVG из документа чистой функцией (ось Y отражена одним внешним `transform`, цвета из справочника, у каждого элемента `data-id`); зоны и объекты скрытых слоёв в текущую картинку не входят и не растягивают её охват (D-173). `planFileName` — одно правило имени файла для `.json` и `.svg` (D-138).

## Граница модуля

codec.ts и organizer-import.ts не зависят от DOM/store. browser-draft.ts — отдельный браузерный адаптер. Открытием и скачиванием управляет features/files.

## Файлы по плану

Следующие файлы создаются при реализации соответствующих пакетов:

- `codec.ts` — IO01.
- `organizer-import.ts` — IO02.
- `browser-draft.ts` — IO03.
- `plan-svg.ts` — картинка плана (D-138).
- `format.ts` — IO03 (определение формата открываемого файла).

**Проверки:** unit-тесты рядом с реализацией; публичные контракты и граничные случаи из карточки пакета.
