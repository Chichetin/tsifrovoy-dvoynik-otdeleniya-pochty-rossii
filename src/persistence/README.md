# src/persistence

Версионированный формат, импорт примера организаторов, локальный черновик.

**Владелец:** поток 3. **Пакеты:** IO01 IO02 IO03.
`codec.ts` реализован пакетом IO01: `decodePlan`/`encodePlan` — единственная дверь между текстом файла и `PlanDocument`. Сохранение канонично (D-022) и отказывает на документе, который сам же не прочитает (D-023); нечитаемая структура и исправимая геометрия — разные исходы: пересечения и самопересечение полигона открываются для правки, битая ссылка и будущая версия — нет. `organizer-import.ts` реализован пакетом IO02: переводит `example_plan.json` в наш документ, не меняя сам пример — типы сопоставляются со справочником команды (D-025), заявленная связь объект→зона и геометрические ошибки примера сохраняются, вложенность зон восстанавливается по геометрии (D-026), а придуманные величины подписаны в `extensions` (D-027). `browser-draft.ts` ещё не реализован.

## Граница модуля

codec.ts и organizer-import.ts не зависят от DOM/store. browser-draft.ts — отдельный браузерный адаптер. Открытием и скачиванием управляет features/files.

## Файлы по плану

Следующие файлы создаются при реализации соответствующих пакетов:

- `codec.ts` — IO01.
- `organizer-import.ts` — IO02.
- `browser-draft.ts` — IO03.

**Проверки:** unit-тесты рядом с реализацией; публичные контракты и граничные случаи из карточки пакета.
