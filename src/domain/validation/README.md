# src/domain/validation

Диагностика ID, связей, границ, коллизий и правил расстояния.

**Владелец:** поток 1. **Пакеты:** V01.
Реализовано пакетом V01: `validatePlan(plan)` возвращает `Issue[]` с кодами, ссылками на `id` и полигоном для подсветки, документ не меняет. Серьёзность идёт от источника правила (D-030), невычислимая геометрия сообщается одна (D-031), расстояние до входа меряется до середины проёма (D-032). Одна проблема — одна находка: объект вне своей заявленной зоны не повторяется находкой связей `ZONE_UNASSIGNED` (D-157). Ошибки примера организаторов закреплены в `tests/example-plan-checks.test.ts`. Коллизии: отпечатки и охваты считаются один раз, полигоны проверяются только у пар с общим охватом и высотой (D-205).

Зоны делят пол только по вложенности: две зоны с общей площадью, из которых ни одна не лежит целиком в другой (включая совпавшие по границе), дают одну находку `ZONE_OVERLAPS_ZONE` — предупреждение с обоими названиями и подсветкой меньшего контура (D-223). Без неё человек видел только по метке «двойная принадлежность» на каждом объекте общей части.

Одинаковый непустой инвентарный номер (`inventoryNumber`, читается как в перечне — обрезанная строка или число) у двух объектов даёт предупреждение `OBJECT_DUPLICATE_INVENTORY_NUMBER` на каждый повтор: первой ссылкой идёт повтор, второй — первый владелец номера по порядку плана, подсвечивается след повтора (D-265). Расстояния в сообщениях печатаются русским форматом `src/domain/number-format.ts`.

Текст самих находок рассчитан на сотрудника (D-219): правила комплектования называют тип оборудования из справочника, расстояние — «главный вход», пересечение — «наружная стена» или «перегородка». Технические `ot_*`, `op_*`, `w_*` остаются в `refs` для перехода к объекту, но не подменяют название в предложении; неизвестный тип остаётся видимым по id.

## Граница модуля

Потребляет contracts, geometry, relations, catalog и вычисление наружных стен из commands. Возвращает Issue[], не исправляет план молча.
