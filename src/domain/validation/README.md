# src/domain/validation

Диагностика ID, связей, границ, коллизий и правил расстояния.

**Владелец:** поток 1. **Пакеты:** V01.
Реализовано пакетом V01: `validatePlan(plan)` возвращает `Issue[]` с кодами, ссылками на `id` и полигоном для подсветки, документ не меняет. Серьёзность идёт от источника правила (D-030), невычислимая геометрия сообщается одна (D-031), расстояние до входа меряется до середины проёма (D-032). Одна проблема — одна находка: объект вне своей заявленной зоны не повторяется находкой связей `ZONE_UNASSIGNED` (D-157). Ошибки примера организаторов закреплены в `tests/example-plan-checks.test.ts`. В тексте находок тип оборудования назван подписью из справочника, а не кодом (правило D-122); у стен и проёмов имени нет — их `id` стоит без кавычек (operator 20.09 №8). Коллизии: отпечатки и охваты считаются один раз, полигоны проверяются только у пар с общим охватом и высотой (D-205).

## Граница модуля

Потребляет contracts, geometry, relations и catalog. Возвращает Issue[], не исправляет план молча.
