**Статус:** исследование дизайна; пользователь выбирает направление. Это не принятый дизайн и не реализованная UI-фича.

Визуальный ориентир — существующий снимок `.playwright-mcp/maxim-01-normal.png` от 22 сентября в основной рабочей копии; это исторический снимок, не новый браузерный прогон.

## Что может приблизить оценку к лидеру

| Критерий | Вес | Действие и доказательство |
|---|---:|---|
| 2D-редактор | 30% | Исправить атомарное изменение X/Y (#1); ясные инструменты и выделение, подписи без перекрытий, больше полезной площади плана; свежий замер на 100/500/1000 объектах |
| Модель, инвентаризация, справочники | 20% | На защите показать связь предмета с записью инвентаризации, сохранение ID/атрибутов и добавление типа через данные; расширение уже существует, его нужно продемонстрировать |
| Ассистент | 20% | Исправить повторное применение кандидата (#2) и связь чисел с метриками (#3); показать основание, объекты/зоны, эффект и ограничения; сравнение файлов (#5) |
| Загрузка/сохранение | 15% | Явное сохранение (#6), открытие демо (#4), пройти сохранение и повторное открытие с сохранностью данных |
| Воспроизводимость | 10% | Согласованные README, рабочий адрес, ZIP и актуальный PDF; репетиция сценария на конкретном релизе (#7) |
| 3D | 5% | Показать соответствие изменённому 2D-плану; условная геометрия достаточно соответствует условиям |

Порядок: надёжность #1–#3 → выбранная композиция UI с #4/#6 → сравнение #5 → релизный комплект #7. Материалы #7 готовятся параллельно. 6–7 октября разумно оставить на стабилизацию, повторяемую демонстрацию и защиту. Изъятая по просьбе пользователя отдельная задача тестирования с незнакомыми людьми не возвращается.

## Наблюдения по существующему экрану

- Верхняя строка смешивает создание геометрии, режим просмотра и файлы; приоритет действий слабый.
- Библиотека, таблица инвентаризации и план одновременно конкурируют за ширину.
- На показанном снимке подписи предметов обрезаны, часть подписей зон перекрывается. В плотном плане нужна управляемая детализация: силуэты и основные названия, полная карточка по выбору.
- Сохранение спрятано под экспортом; объяснение ассистента и эффект изменения стоит связать с конкретными местами на плане.

## Общий бриф

Аудитория — руководитель отделения, проектировщик и специалист инвентаризации. Задача экрана: открыть синтетический план, найти проблему, изменить объект и сохранить проверяемый результат. Desktop 1440×900, контроль 1280×800; концепты рисуются приблизительно в 16:10. В генерациях геометрия иллюстративная: их нельзя использовать как точный эталон координат или сохранённый план.

Иерархия: документ и сохранение → рабочий режим → план → контекст выбранного объекта → детали по раскрытию. Постоянные действия: открыть/демо, сохранить, отменить/повторить. Состояния будущей реализации: пустой план, выбранный объект, несохранённые изменения, отказ по геометрии, загрузка/ошибка файла, работа ассистента и fallback. Все кнопки доступны с клавиатуры; ошибки различаются текстом/значком, а не только цветом. Для числовых полей — общая явная фиксация координат.

## A. Светлый рабочий редактор — рекомендуемая основа

- Компактная шапка документа, отдельные режимы «Редактор / Инвентаризация / Сравнение».
- Слева библиотека/слои, по центру самый крупный план, справа только контекст выбранного объекта или ассистента.
- Основной акцент — ясное выделение на плане и связанная с ним карточка действия.
- Цвета: белый `#FFFFFF`, фон `#F3F6FA`, синий `#075CCB`, текст `#172B44`, зелёный `#258376`, янтарный `#AD6415`.
- Типографика: направление Golos Text для заголовков, PT Sans для интерфейса, табличные цифры. Точный шрифт и лицензии проверяются при реализации.
- Плюсы: читается на проекторе, близок существующей структуре приложения, проще внедрить до защиты.
- Цена: потребуется переразложить шапку/панели и их состояния. Узкую библиотеку и таблицу нужно проверять на целевых размерах.

## B. Инженерная мастерская — альтернатива

- Узкая полоса инструментов слева, большой чертёж с линейками, точные свойства справа, раскрываемая инвентаризация снизу.
- Акцент — точная работа с объектом и координатами; библиотека открывается по запросу.
- Цвета: оболочка `#142230`, панели `#203343`, холст `#0D1B26`, текст `#E7EEF3`, выделение `#72B8FA`, успешное состояние `#61CCAF`.
- Типографика: направление IBM Plex Sans и IBM Plex Mono для чисел.
- Плюсы: много места для чертежа, привычно специалистам CAD.
- Цена: больше изменений компоновки и цветовых состояний. Читаемость тёмного плана на проекторе нужно проверять. До защиты не стоит поддерживать два полноценных оформления одновременно.

## C. Сравнение для решения — дополнительный экран

- Два плана в одном масштабе «было / стало», справа объяснение изменений, снизу компактная таблица эффектов.
- Акцент — связь изменения конкретного предмета с проверяемым результатом. Этот экран может дополнять вариант A или B.
- Цвета: белый, тёмная шапка `#15385D`, синий `#075CCB`, светлый фон `#EAF2FB`, текст `#213445`, зелёный `#22745E`; снижение свободной площади не отмечается как безусловный успех.
- Типографика совместима с вариантом A.
- Плюсы: позволяет руководителю и жюри понять пользу выполненной перепланировки.
- Цена: требует отдельного выбора базы сравнения (#5); синхронизация масштаба/выделения — дополнительная UI-работа.

Точные факты из `demo/effect.md`: расстояние терминала до входа **6,62 → 2,25 м**, ошибки **1 → 0**, скамьи **1 → 2**, свободная площадь **114,73 → 113,93 м²**, объектов **53 → 53**. Стоимость дополнительной скамьи — **0,80 м²** свободной площади. Это не измерение очереди или экономии денег. Условие расстояния — правило команды, не утверждение о нормативе.

## Рекомендация и следующий шаг

Выбрать **A как основной редактор + C как сравнение**. B оставить альтернативой при явном предпочтении команды. До защиты реализовать один вариант рабочего интерфейса. После выбора согласовать короткий список экранов и критерии приёмки, разложить изменения по владельцам и связать с существующими issues, не дублируя их.

Это визуальное исследование, поэтому полный UI gate не заявляется пройденным. Реализация потребует всех навыков и доказательств из `CLAUDE.md`: браузерный round-trip, снимок, автоматические и ручные проверки доступности, проверка рекомендаций по интерфейсам.

## Метод и артефакты

Применены `brainstorming`, `ui-ux-pro-max`, `frontend-design`, `imagegen`. Поиск `ui-ux-pro-max` с запросами `floorplan editor desktop workspace` и уточнением `engineering CAD desktop` вернул нерелевантную структуру лендинга Hero/CTA; эта структура не использована. Компоновка выведена из задач редактора и существующего UI, общие требования контраста/фокуса применены как базовые рекомендации.

Три самостоятельных превью заказаны встроенному imagegen. Все три изображения A/B/C готовы, визуально просмотрены и сохранены в репозитории. Пользователь запросил изображения для выбора; это концепты, не скриншоты работающих функций. Промпты задают предметную область, русский язык, отдельную композицию каждого варианта, конкретные элементы и проверенные демо-числа. Следующий шаг после выбора направления — согласовать конкретную компоновку и задачи реализации.
