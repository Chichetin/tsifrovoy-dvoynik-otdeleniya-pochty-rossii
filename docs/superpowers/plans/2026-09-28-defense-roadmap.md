### Подтверждённые дефекты и пробелы

1. **Координаты нельзя всегда изменить через карточку, даже если конечное место свободно.** `src/features/properties/PropertiesPanel.tsx:200` и `:497` отправляют каждую координату отдельно. На `demo/before.json` скамья из `after.json`, поставленная в `[7.5, 1]`, не переносится полями в `[2.2, 2]`: `[2.2, 1]` и `[7.5, 2]` дают `OBJECT_COLLISION`; единая команда в `[2.2, 2]` проходит. Подтверждено свежим запуском store через `node --import tsx`. В `tests/e2e/demo.spec.ts:129` уже документирован обход через специально выбранную точку клика.
2. **Цикл «применить кандидата → удалить → спросить снова → применить» ломается.** `placement.ts:646` учитывает существующие ID, но не retired; `App.tsx:647` отправляет ID кандидата напрямую. Store правильно отказывает в повторном использовании (`src/state/plan-store.ts:190`). Свежий запуск для `ot_queue_terminal`/`z_entrance`: добавление и удаление успешны, повторный кандидат имеет тот же ID, применение → `ID_REUSED`. Конкретный суффикс ID зависит от выбранного кандидата и не является условием бага.
3. **Свободный чат проверяет наличие числа, но не смысл утверждения.** `src/domain/advice/agent-text.ts:62` собирает общий набор чисел из результатов и вопроса; `:94` проверяет принадлежность этому набору. Для реального `plan_overview` демо проверка приняла «Свободная площадь помещения — 132 м²», хотя 132 — полная площадь, а свободная — 114,73. Число 99999 из вопроса также позволило принять ответ с такой площадью. Это свежий детерминированный вызов `checkAgentText`, не наблюдение галлюцинации живой модели. У структурированных рекомендаций отдельный механизм проверки; находка не означает, что все расчёты ассистента неверны.
4. **Комплект презентации расходится с продуктом.** PDF `output/pdf/posttech-digital-twin-2026-09-18.pdf` — черновик со словами об отсутствии публичного адреса и неподтверждённом вызове LLM. README и `docs/submission.md` называют его черновиком. Неизвестно, именно ли этот файл был отправлен жюри.
5. **Сравнение привязано к текущей сессии.** `src/app/App.tsx:552`/`:591` передаёт `baseline` из store. При открытии нового файла исходная база заменяется. Самостоятельное сравнение выбранных `before.json` и `after.json` требует отдельного пользовательского действия/базы сравнения; не следует путать его с уже существующим эффектом изменений текущей сессии.
6. **Первый вход требует лишних действий.** Файлы демо уже доступны по HTTP — старая проблема отсутствующего `/demo/` исправлена. Однако `src/features/onboarding/tour.ts:33` предлагает вручную скачать и открыть файл, прямого открытия демо из обучения нет.

Не переносить старые баги автоматически в новый backlog. Например, таймаут `assistant-request-race` уже увеличен; сегодняшний unit-набор зелёный. `spawnSync(... timeout:4000)` в placement-тесте остаётся риском на нагруженной машине, а не доказательством красного main.

## Что отложить

До защиты не планировать OCR/PDF/DWG, видеопотоки, 1С, фотореалистичное 3D, многопользовательскую платформу и переписывание архитектуры. HTTPS/домен — небольшая условная задача, только если другой браузер/сеть не открывает текущий адрес или это требуется регламентом; миграция инфраструктуры не должна мешать рабочему показу.

P2 после основных ворот: атрибуты в CSV/инвентаризации, улучшение ракурса и подписей 3D, локальные ускорения фильтра. Их брать по результатам проверки людьми или профилирования, а не по старому списку пожеланий. Проверку проходов/доступности маршрутов вынести в отдельное исследование после защиты либо пересмотреть приоритет только при прямом замечании жюри.

## Общие правила готовности

Только синтетические данные; разрешённые LLM по API; секреты вне git; числа считает код. Новая логика и багфиксы получают осмысленные тесты. Для каждой реализации UI обязателен полный skill gate из `CLAUDE.md`: дизайн, браузер, снимок, accessibility и web guidelines. Эта дорожная карта UI не меняет и прохождение такого gate за будущие функции не заявляет.

Каждый пакет — свой worktree, журнал решения и обновление соответствующей строки `docs/tz-compliance.md` при фактическом закрытии требования, проверки, commit и MR. Само планирование новых требований не закрывает. Перед коммитом и после длинного шага — оба обязательных хука. Владельцы и точные файлы фиксируются до начала пакета; в общие файлы изменения интегрируются последовательно.
