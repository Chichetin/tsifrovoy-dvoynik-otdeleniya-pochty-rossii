> Задача [#60](https://git.codenrock.com/codenrock/khakaton-postcode-challenge-ot-pochtatekha/ii-blanki/tsifrovoy-dvoynik-otdeleniya-pochty-rossii/-/issues/60).

**Цель:** рабочий экран проще — название плана и состояние сохранения всегда на виду, а всё, что
настраивается один раз на проект, собрано в одном окне «Настройки».

**Принцип (слова участника):** «вынести туда настройки, которые не часто используются, которые один
раз настраиваются в проекте, — тогда можно облегчить функционал». На экране остаётся ежедневное:
инструменты, библиотека, видимость слоёв, свойства, ассистент, проверка, инвентаризация.

## Ограничения

- Формат файла и контракты (`src/contracts/*`) не меняются: только перестановка существующих
  элементов и существующих команд (`plan.rename`, `room.setCeiling`, команды справочника и слоёв).
  Демо-планы и ZIP не затрагиваются.
- Граница импортов: feature не встраивает другую feature, поэтому шапка и окно собираются в
  `src/app/` (как `SideTabs`: панели передаёт `App.tsx`).
- Шапка — одна строка 48 px на 1280–1920 px (D-254, D-260, D-316); `tests/e2e/shell.spec.ts`
  проверяет, что ничего не обрезано.
- `h1` «Цифровой двойник ОПС» остаётся — по нему шесть e2e узнают, что приложение загрузилось.
- UI/UX skill gate из `CLAUDE.md` для каждого шага; доказательства — в описании MR.

## Шаг 1. Название плана и состояние сохранения в шапке

Первая колонка шапки — две строки: мелкий бренд (`h1`, вид подписи) и под ним название плана
кнопкой. Название не помещается — многоточие, полное в подсказке.

- Клик по названию → поле `aria-label="Новое название плана"`, текст выделен. Enter или уход
  фокуса — `plan.rename`; Esc — отмена; без изменений — ничего не отправляется. Пустое после обрезки:
  Enter — подсказка «У плана должно быть название.» у поля (`aria-describedby`), поле остаётся;
  уход фокуса — отмена.
- Отказ команды — тем же путём, что у любой правки (`dispatch` → плашка «Правка отклонена»).
- Состояние сохранения — значок после названия, форма и цвет вместе: `●` оранжевый «Есть
  несохранённые правки» (`dirty`), `✓` зелёный «Сохранено в файл». Текст — в `title` и для
  скринридера (`role="status"`). Новый план — `dirty` (store так и считает: он нигде не сохранён).
- Поле «Название плана» в карточке помещения пока остаётся (уберёт шаг 2 вместе с высотой потолка).
- Решение D-350 заменяет часть D-152 («название живёт в карточке помещения»).

Файлы:
- создать `src/app/plan-title.ts` — чистая `renameOutcome(draft, current)`:
  `{ kind: 'cancel' } | { kind: 'empty' } | { kind: 'rename', name }`; `name` — как набрано (D-152:
  обрезку делает команда только для проверки пустоты);
- создать `src/app/plan-title.test.ts`;
- создать `src/app/PlanTitle.tsx` — `PlanTitle({ name, dirty, onRename })`, `onRename(name)`
  возвращает `boolean` (принята ли команда);
- создать `src/app/PlanTitle.test.tsx` — Testing Library: показ, Enter, Esc, blur, пустое, значок;
- изменить `src/app/App.tsx` (шапка), `src/app/styles.css` (`.shell__doc…`);
- e2e: `tests/e2e/plan-title.spec.ts` — открыть демо → переименовать в шапке → значок «●» →
  Экспорт JSON → «✓» → открыть файл заново → название то же.

Проверки: `npm test -- src/app/plan-title.test.ts src/app/PlanTitle.test.tsx`,
`DEV_PORT=5174 npm run test:e2e -- tests/e2e/plan-title.spec.ts tests/e2e/shell.spec.ts`,
`npm run typecheck && npm run lint && npm run build`, снимок шапки 1280×800 и 1920×1080.

## Шаг 2. Окно «Настройки»: План, Оборудование, Зоны, Правила

- Кнопка «Настройки» (шестерёнка + подпись, на узкой шапке только значок с `aria-label`) открывает
  модальный `<dialog>` ~960×640: слева разделы, справа содержимое. Закрытие — ✕, Esc, клик мимо;
  фокус возвращается на кнопку.
- «План»: название (то же `plan.rename`) и высота потолка (`room.setCeiling`); из карточки помещения
  оба поля уходят, остаются площадь и подсказка про контур.
- «Оборудование», «Зоны», «Правила» — три раздела нынешнего `CatalogPanel`
  (`section: 'objects' | 'zones' | 'rules'`); вкладка «Справочник» справа исчезает.
- Правки применяются сразу командами, как сейчас; отмена работает; план за окном обновляется.

Файлы: создать `src/app/SettingsDialog.tsx` (+ тест; список разделов — константа в нём, отдельный
`settings-sections.ts` не понадобился); изменить
`src/app/App.tsx`, `src/app/side-tabs.ts` (без `catalog`; сохранённое `catalog` в `localStorage`
→ вкладка по умолчанию), `src/features/catalog-editor/CatalogPanel.tsx` (проп `section`),
`src/features/properties/PropertiesPanel.tsx`; e2e, ходившие во вкладку «Справочник», —
через «Настройки»; шаги обучения (`src/features/onboarding/tour.ts`), README, `docs/tz-compliance.md`.
