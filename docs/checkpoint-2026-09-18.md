# Контрольная точка 18.09 — рассказ для экспертов на 1–2 минуты

Все числа ниже — из прогонов на `main` 18.09.2026, не оценки. Что показывать
вживую — в конце.

## Текст (≈ 90 секунд)

Мы делаем цифровой двойник отделения: веб-редактор плана, где отделение
рисуется с нуля — контур помещения, перегородки и проёмы, зоны, оборудование
из библиотеки. Всё это одна модель данных: перечень оборудования, площади и
проверки считаются из того же документа, что и картинка, поэтому разойтись они
не могут.

**Три вещи, на которых стоит решение.**

Первое — справочники живут в данных, а не в коде. 25 типов оборудования по
перечню организаторов, 8 типов зон, 6 правил комплектования — всё в JSON.
Новый тип добавляется правкой файла, появляется в библиотеке и на плане без
единой строки кода; это проверено автотестом.

Второе — проверка корректности. Мы взяли пример организаторов как тестовый
набор: редактор находит в нём все известные дефекты — три пары пересекающихся
объектов, стеллажи сквозь перегородку, терминал очереди в 6,9 м от входа при
норме 3 м. Каждая находка ведёт к объекту на плане, и правило, которое мы
придумали сами, подписано «допущение команды, не норматив Почты».

Третье — ассистент, который не врёт в числах. Площади, свободный пол, поиск
места, недостающее оборудование считает детерминированный код с тестами.
Модель по API — только DeepSeek или Qwen, доступные в РФ — выбирает сценарий и
формулирует объяснение из уже посчитанных фактов; ответ проверяется кодом, и
если модель сослалась на несуществующий id или число, показывается расчёт.
Без ключа сервис работает полностью, с пометкой «без LLM».

Сохранение — свой версионированный JSON со снимком справочника внутри: план
с пользовательским типом откроется на другой машине. 3D строится из того же
документа автоматически.

**Что измерено.** 477 unit-тестов, 53 браузерных сценария, все зелёные.
Масштабируемость: план на 1000 объектов и 50 зон открывается за 4,5 с,
выделение объекта — 180 мс, полная проверка — 200 мс. Деплой — `docker compose
up`, один файл `.env`.

**Что не сделано и о чём хотим спросить.** Нет публичного адреса — ждём ответ
о хостинге. Демо-рекомендация получена в режиме без LLM: ключа провайдера у
команды пока нет. GigaChat и YandexGPT говорят на своём протоколе — адаптера
нет. Вопрос к экспертам: какие правила комплектования вы считаете реальными,
чтобы мы заменили ими наши допущения.

## Что показать (порядок, 60 секунд)

1. Открыть `demo/before.json` кнопкой «Открыть» — 8 зон, 53 объекта, панель
   проверки сразу показывает три намеренных нарушения.
2. Нажать «Проём», кликнуть по перегородке — проём встал; «Отменить» — исчез.
3. Перетащить стеллаж на кассу — коллизия появляется в списке проверок мгновенно.
4. Вкладка ассистента → «Место для рабочего места» → кандидат подсвечен
   полупрозрачно, объяснение с числами «было → стало».
5. Переключить 3D — та же сцена.
6. «Сохранить» → «Новый» → «Открыть» сохранённый — всё на месте.

## Запуск демо на своей машине

```bash
npm ci
DEV_PORT=5173 npm run dev     # http://127.0.0.1:5173
```

Если ассистент нужен с моделью — заполнить `.env` по `.env.example`
(`LLM_API_KEY`, `LLM_MODEL` из документации провайдера). Без него ассистент
работает в режиме расчёта.
