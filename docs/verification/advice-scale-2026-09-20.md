# Ассистент на больших планах: замер расчёта (D-205)

**Дата:** 2026-09-20 (ночь). **Машина:** Intel Pentium G3220 (2 ядра), Windows 10,
Node 22 (portable). **Код:** «до» — `main` `f774663`; «после» — ветка
`worktree-advice-scale` (тот же коммит плюс правки D-205).
**Команда:** `npx tsx scripts/measure-advice.ts` — медиана трёх прогонов каждого шага,
планы — `scripts/generate-benchmark.ts` (100/500/1000 объектов, 10/30/50 зон),
сценарий `place` — первый тип справочника в первой зоне, `compare` — план с самим собой.
Без браузера и без сети: это чистый расчёт, который сервер делает до обращения к модели.

## Что было

Расчёт «место для объекта» на 1000 объектов занимал **44,7 с** — дольше таймаута
модели и любой разумной паузы в интерфейсе; на 500 объектов — 10,5 с. Профиль
(`node --cpu-prof`) показал три источника: `measurePlan` пересекал объединение всех
отпечатков с каждой зоной целиком (`polyclip-ts` на длинной арифметике: 5,9 с на 1000
объектов — четыре вызова на одну рекомендацию), `validatePlan` пересчитывал отпечаток
на каждую пару объектов при проверке коллизий (полмиллиона пар), а `resolveZone`
проверял каждую зону на самопересечение заново для каждого объекта (100 000 проверок).

## Что сделано

- `metrics`: объединение отпечатков режется на куски; для зоны берутся только куски,
  чей охват задевает охват зоны; куски целиком внутри зоны и без двора считаются
  своей площадью, режутся полигонами только те, что лежат на границе.
- `validation`: отпечатки, охваты и высотные интервалы считаются один раз; пара
  проверяется полигонами только после совпадения охватов и высот.
- `relations`: `prepareZones(zones)` — пригодность, охват и глубина каждой зоны один
  раз на план; `resolveZone` берёт индекс третьим параметром, `relationIssues`,
  `reconcileZones` и перебор мест ассистента передают его.

Ответы не изменились: `measurePlan`, `validatePlan` и `calculateAdvice(place)` на
100/500/1000 объектов и на `demo/before.json`, `demo/after.json`, `nested.json`
сравнены с сохранённым JSON до правок — совпадение побайтно (площади — разница 0).
Равенство сокращённого пути полной обрезке закреплено тестом
`metrics.test.ts` «локальная обрезка даёт то же, что полная»; мутанты «без проверки
`contains`», «без проверки двора», «кусок вне охвата считается», «без проверки
полигонов в коллизиях», «зона по охвату без `contains`» — красные.

метрик и здесь не делалось.

## Что не проверялось

Время ответа `/api/advice` с сетью и моделью — см. [живой прогон](llm-live-2026-09-19.md);
браузерная часть (панель ассистента) не менялась. На Ryzen AI 9 этот скрипт не
запускался; по замеру открытия в браузере ([19.09](performance-2026-09-19.md)) та
машина в 2,5–4 раза быстрее этой — это оценка, не измерение; пересчёт на коммите
сдачи желателен.
