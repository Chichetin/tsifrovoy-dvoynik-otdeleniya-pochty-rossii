## Поведение

LLM по-прежнему выбирает инструменты, подсветку, панели и кандидата. Результат каждого инструмента содержит answerFacts: готовые утверждения с ключами, связанными с конкретной метрикой, областью, фазой, значением и единицей. Для итогового ответа модель выбирает только factIds. Сервер принимает лишь опубликованные факты и пишет текст кодом. Значения из вопроса или истории не являются доказательством; проза рядом с toolcalls не показывается. При несовпадении кандидата и предлагаемого действия выбор отвергается.

Режим `llm` означает выбор инструментов/фактов моделью; числовые предложения не являются свободным текстом модели. Подпись в интерфейсе и README уточнены. HTTP/NDJSON и файл плана сохраняют прежнюю форму. После одного неверного исправления показывается корректный расчёт с «Без LLM»; уже рассчитанные рекомендации и действия сохраняются.

Tool-result всегда остаётся валидным JSON в бюджете 8000 символов. При большом подробном результате сохраняется компактный справочник типов, слоёв, зон и кандидатов; имена сокращены только в контексте модели. Непомещающийся факт пропускается, а не блокирует все последующие факты. Пропуски обозначены явно; можно вызвать zone_details. В отображаемом ответе внутренние handles кандидата/рекомендации скрыты, вариант различается номером, центром и поворотом.
