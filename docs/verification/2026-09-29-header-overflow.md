На Windows системный шрифт уже, поэтому прямой прогон не воспроизводил те же 13 px. Перед правкой новый тест с искусственным расширением подписей падал: при 1280 px шапка выходила за окно на 1 px, при 1460 px свободная колонка была уже требуемых 20 px.

Стресс требует отсутствие вылета и свободную колонку ≥20 px; граничные 1339/1340 и 1500 проверяют переключения CSS-правил.
- Снимки [1280](2026-09-29-header-1280.png) и [1460](2026-09-29-header-1460.png) сняты **после** применения расширенного интервала и осмотрены: «Демо», «Экспорт» и все группы кнопок видны в одной строке. Фокус (`shell.spec.ts:276`) и контраст (`shell.spec.ts:287`) в шапке — существующие проверки, не новые для этого пакета; в общем прогоне `shell.spec.ts` они тоже зелёные.

- Независимое ревью diff не выявило блокеров для draft MR; проверка исходного Linux-проявления остаётся обязательной перед merge.

Это fallback проверки UI: доступные в этой сессии навыки полного UI/UX gate отсутствуют. Локальный Windows-прогон и искусственно расширенный шрифт не являются доказательством исправления именно на Linux. Автор исходной находки должен повторить `CI=1 npx playwright test tests/e2e/shell.spec.ts --workers=1` на Linux и подтвердить отсутствие вылета на 1280/1460 перед снятием блокера #44.

## Проверка на Linux (D-319, продолжение #44 после ассайна на alecksandrchicherin)

Исходный Linux-прогон **воспроизвёл** описанное выше: `DEV_PORT=5345 CI=1 npx playwright test tests/e2e/shell.spec.ts tests/e2e/open-demo.spec.ts --workers=1` — 26 passed, 2 failed. Красным был только новый стресс-тест `shell.spec.ts:164`: `overflow` ≤ 0 (переполнения нет), но `slack` меньше `MIN_SLACK_PX = 20` — **1280 px: 15,2 px, 1460 px: 13,5 px**. Базовый `shell.spec.ts:172` («одна строка…») зелёный на всех шести ширинах, `open-demo.spec.ts` зелёный — исходная находка #44 (13 px переполнения) закрыта уже коммитом D-316; красным был только новый запас.

D-319 добрал недостающие 4,8/6,5 px, сняв ещё по 1 px горизонтального поля с каждой стороны у шести подписанных кнопок инструментов (`padding-inline: 5px → 4px`, `.shell__bar .toolbar__button`, ≤1500 px). Измерено отдельным Playwright-скриптом (та же стресс-модель: клик «Перегородка», две точки на холсте, `letter-spacing: 0.4px` на кнопках шапки) до и после правки:

| Ширина | Slack до D-319 | Slack после D-319 | Порог |
|---|---|---|---|
| 1280 px | 15,2 px | **27,3 px** | ≥ 20 px |
| 1460 px | 13,5 px | **25,6 px** | ≥ 20 px |

Тем же скриптом подтверждено, что D-316 (не D-319) первым ввёл `min-width: 44px` у `.shell__bar .toolbar__button` — этого правила у main не было. Оно перебивает `width`/`min-width: 30px` у `.toolbar__button--icon`: иконка «Удалить перегородку» на ≤1500 px стала 44×30 px вместо 30×30, «Зона» — 44 px вместо естественных ~40 px. D-319 их дальше не трогает (для кнопки-иконки любое значение `padding-inline` ниже 44 px roли не играет — ширину всё равно задаёт `min-width`). Высота всех кнопок инструментов везде осталась 30 px, как на main; расширение — только по ширине и только зона нажатия.
