# Q02 — локальный замер масштабируемости редактора

На базовом `main` `d02ecb8` (18.09.2026) Chrome 153.0.8010.12 на Windows
10.0.26200, AMD Ryzen AI 9 365 (20 логических потоков), RAM 24.8 GB.
Результаты — пять последовательных прогонов на каждом объёме в отдельном
контексте браузера. [Сырые выборки](performance-raw.json) включают каждый
прогон, user agent, CPU, RAM, seed `20260918` и commit. Синтетический генератор
создаёт 100/500/1000 физических объектов и 10/30/50 зон в помещении 100×50 м;
объекты не пересекаются. Реальные планы могут вести себя иначе.

| Объекты / зоны | Первое открытие p50/p95 | Повторное открытие p50/p95 | Выделение p50/p95 | Полная валидация p50/p95 | Сохранить → новый → открыть p50/p95 |
|---|---:|---:|---:|---:|---:|
| 100 / 10 | 309 / 388 мс | 130 / 166 мс | 55 / 79 мс | 4 / 5 мс | 290 / 313 мс |
| 500 / 30 | 1354 / 1381 мс | 1102 / 1134 мс | 155 / 172 мс | 60 / 64 мс | 1301 / 1319 мс |
| 1000 / 50 | 4470 / 4486 мс | 4138 / 4232 мс | 176 / 187 мс | 200 / 208 мс | 4657 / 4760 мс |

В таблице миллисекунды округлены. `p50` — третье, `p95` — пятое из пяти
отсортированных значений (nearest rank). Сценарий запускается через
`npm run test:perf -- tests/perf/editor.spec.ts`; использует установленный Chrome
и отдельный `DEV_PORT` (по умолчанию 5187), отказывается от занятого порта.
На этой Windows-машине остановка автоматически запущенного Vite через Playwright
зависала после прохождения тестов. Зафиксированные выборки сняты с отдельно
запущенным Vite на порту 5187 и `PW_REUSE_SERVER=1`; команда завершилась
`3 passed (1.7m)` с кодом 0. Перед повтором в этом режиме убедиться, что
сервер запущен из **того же** worktree: флаг сознательно разрешает повторное
использование сервера.
Результат сохраняется в `test-results/**/samples.json`, а копия использованных
здесь значений — в `performance-raw.json`. Никаких данных почтовых отделений в
генераторе нет.

Первое открытие измерено от загрузки файла до появления всех строк
инвентаризации. Повторное открытие — после сброса плана, на уже открытой
странице. Выделение — клик по первому объекту до появления его `id` в карточке.
Полная валидация — отдельный вызов `validatePlan` в браузере с этим документом,
без React и перерисовки. Последняя колонка включает скачивание, сброс и
повторное открытие сохранённого файла. Время `page.goto` и холодный запуск
процесса Chrome в первую колонку не включены. Загрузка и взаимодействие
измеряются через Playwright с накладными расходами его ожиданий; это не чистое
время кадра. В сырых данных `heapBytes` — доступный Chromium JS heap в конце
прогона, не общая память приложения и не независимый замер пика.

На 1000 объектах открытие занимает около 4 секунд; это ограничение для
демонстрации больших планов. На этих данных
`validatePlan` занимает лишь около 0.2 с по медиане, поэтому без отдельного
профиля нельзя приписывать всю задержку геометрии или вводить spatial index/
worker. Перед сдачей Q02 следует повторить на собранном release candidate и
том же сценарии; цифры здесь относятся к указанной базе и машине.
