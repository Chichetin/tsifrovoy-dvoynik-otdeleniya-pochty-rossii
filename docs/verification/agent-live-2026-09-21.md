# Живой прогон агента по плану (D-258), 21.09.2026

Модель: DeepSeek-V4-Flash через OpenAI-совместимый API Yandex Cloud AI Studio
(`LLM_ENDPOINT=https://llm.api.cloud.yandex.net/v1/chat/completions`, ключ в `.env`,
в репозиторий не попадает). План — `demo/before.json`.

**Оговорка.** Оба прогона сделаны до трёх последних правок ветки: запрет служебных
`id` вариантов в тексте, статус «Применено…» и пометка модели «план изменился после
прошлого ответа». Повторный прогон после этих правок был прерван и в запись не вошёл.

## 1. Цикл `runAgent` напрямую (скрипт на `server/agent.ts` + `createLlmChat`)

Предварительная проверка: провайдер вернул `tool_calls` на запрос с `tools`,
`finish_reason: "tool_calls"`, за 3 с.

| Вопрос | Шаги агента | Время | Режим |
|---|---|---|---|
| Где поставить ещё одно кассовое окно поближе к входу? | plan_overview, list_objects, find_place (Клиентский зал), zone_details (Входная группа), suggest_candidate, show_on_plan | 28,9 с | `llm` |
| Чего не хватает в зоне ожидания? | plan_overview, list_objects, zone_details, check_equipment, find_place (скамья), show_on_plan, suggest_candidate | 31,3 с | `llm` |
| Есть ли в плане ошибки и что исправить первым? | validate_plan, plan_overview, show_on_plan, open_panel (Проверка) | 11,5 с | `llm` |

Ответ на первый вопрос (текст модели, прошёл проверку чисел и `id`): «Лучший вариант —
поставить четвёртое кассовое окно в клиентском зале (z_client) у левой стены, ближе всего к
входной группе (z_entrance)… свободная площадь зала при этом уменьшится с 114,5 до 113,1 м².
…расстояние 3,7 м против 3,9 и 4,5 м у альтернатив… правило … — допущение команды, не
норматив Почты России».

Найдено и исправлено по итогам:
- во втором ответе пропал вывод: модель писала его рядом с вызовами инструментов, а
  в ответ попадал только последний ход — теперь текст всех ходов склеивается и
  проверяется целиком (тест «вывод, сказанный рядом с вызовами…» в `server/agent.test.ts`);
- `list_objects` принимал несуществующий тип `zone` — теперь это ошибка для модели.

## 2. Браузер: `npx tsx server/main.ts` (порт 8080) + `npm run dev` (порт 5290), 1440×900

1. Вопрос «Где поставить ещё одно кассовое окно поближе к входу?» — через 6 с в журнале
   уже были шаги «Сводка плана», «Список оборудования», «Работаю с планом»; ответ за
   22,8 с, `llm`, вариант окна нарисован на плане полупрозрачно. Найдено: модель вписала
   в текст служебный id варианта `adv_ot_cashier_window_6` — исправлено (такие id теперь
   не проходят проверку, модель получает замечание).
2. Вопрос «Где добавить ещё одно рабочее место оператора?» → «Применить: Рабочее место
   оператора» → объект на плане. Найдено: статус показывал «План изменился» вместо
   подтверждения — исправлено.
3. Уточнение «А сколько теперь свободной площади во всём помещении?» — ответ с числами
   текущего плана (113,4 м² из 132 м², занято 18,6 м²), но с оговоркой «до применения
   варианта», хотя вариант был применён. Исправлено: к вопросу добавляется пометка, что
   план изменился после прошлых ответов (тест в `server/agent.test.ts`).

## 3. Повторный прогон на итоговом коде ветки (22.09, после merge `origin/main`, коммит `5e6f1f9`)

Тот же `runAgent` с настоящей моделью из `.env` (провайдер и модель — из переменных
окружения, без браузера), план `demo/before.json`; локальный скрипт вызывает
`createLlmChat` + `runAgent` по одному вопросу:

1. «Где поставить ещё одно рабочее место оператора?» — `mode=llm`, 15,4 с; шаги
   `plan_overview`, `list_objects`, `find_place`, `check_equipment`,
   `suggest_candidate`, `show_on_plan`; ответ называет `z_client`, свободную площадь
   после установки 113,4 м² и правило команды; действия `preview-candidate`,
   `apply-candidate`, `focus`.
2. «Какого оборудования не хватает или какое лишнее?» — `mode=llm`, 5,9 с; шаги
   `check_equipment`, `show_on_plan`; ответ: лишнее табло (`eq_7`/`eq_8` в `z_client`),
   не хватает скамьи в `z_waiting` (есть `eq_6`), с пометкой «допущения команды, не
   нормативы Почты»; действия `focus` ×3.

Оба ответа прошли проверку кодом (иначе был бы режим `fallback`). Браузерный проход
с сервером в этот раз не повторялся — его покрывает `tests/e2e/assistant.spec.ts`
(транспорт и «Применить» без модели).
