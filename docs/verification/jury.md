# Протокол прохода жюри

Статус на 18.09.2026: это исполняемый протокол, **не** отметка о пройденной
внешней приёмке. Его следует выполнить на commit сдачи и сохранить фактические
результаты здесь. Отдельно нужен человек, который не писал README: он выполняет
шаги без подсказок автора.

| Шаг | Действие независимого проверяющего | Критерий | Факт |
|---|---|---|---|
| 1 | Открыть ссылку GitLab и корневой README, записать SHA `origin/main` | Источники доступны, SHA совпадает с заявленным commit сдачи | Не проверено |
| 2 | Запустить сервис по README на чистой машине или открыть опубликованный адрес с другой сети | SPA открылась, `/api/health` вернул `ok`; условия доступа указаны | Локальный Docker и Windows-сервис проверялись ранее; публичный адрес не проверен |
| 3 | Начать с **Открыть** и загрузить собственный `before.json` из ZIP | Видны зоны, оборудование, `id`, типы и атрибуты | E01 из ZIP проверен браузерным тестом 2/2; независимый проход ожидается |
| 4 | Изменить объект и сохранить, перезагрузить страницу и открыть скачанный JSON | Правка, зоны, связи и атрибуты на месте | Q01 автоматизирован на тестовых файлах; ручной проход демо ожидается |
| 5 | Увидеть нарушение, спросить ассистента, применить рекомендацию вручную, сверить `effect.md` | Источник правила и числа совпали; режим LLM назван честно | E01 проверяет данные и ручную правку в браузере; независимый проход ожидается |
| 6 | Переключить 3D и обратно, сопоставить объект и зону с 2D | 3D следует текущему плану, скрытые слои не показываются | Есть автоматические тесты; ручной проход ожидается |
| 7 | Распаковать **один** ZIP внешней программой и открыть оба JSON в редакторе | Все пять файлов комплекта есть, планы редактируются | E01 проверен из ZIP в Chrome 2/2, архив 25 171 Б; стороннюю распаковку на релизе повторить |
| 8 | Открыть PDF и проверить размер | Один читаемый PDF, не более 20 МБ | PDF не предоставлен |
| 9 | Проверить ссылки и вложения в форме сдачи | GitLab, редактор, ZIP, PDF доступны без локального пути автора | Не проверено |

Для релизного прогона записать дату, ОС и браузер, SHA, адрес сервиса, результат
каждого шага и ссылку на опубликованные файлы. Не ставить «пройдено» по одному
лишь автоматическому тесту: он подтверждает конкретный сценарий на конкретной
сборке. Сырые локальные доказательства уже есть в [Q01](e2e.md) и [Q02](performance.md).
