# Browser e2e под нагрузкой — Issue #46

У команды на Linux при load average 13–21 три теста иногда достигают лимита 30 с: `custom-shape.spec.ts`, `focus.spec.ts` и `inventory.spec.ts`. Сохранённый в [разборе #11](2026-09-29-inventory-number.md) A/B на той же машине показал сходное поведение ветки и чистого main. В trace `focus` три движения указателя по 10 шагов стоили по 3,9–4,3 с; у `custom-shape` под нагрузкой таймаут приходился на открытие файла или ожидание вкладки. Постоянная задержка расчёта формы/инвентаризации не доказана. Исходный trace `custom-shape` запрошен у автора #46.

По D-318 browser-тесты выполняют меньше повторных жестов при той же проверяемой логике: в `focus` конечное смещение каждого из трёх переносов то же при двух промежуточных событиях вместо десяти; `inventory` сверяет **каждое** отображённое число с демо-планом точно и проверяет фильтрацию на нескольких типах вместо 24 последовательных циклов; `custom-shape` проверяет вход/выход из режима в коротком независимом сценарии, а полный путь правки формы → типа → размещения → JSON → открытия оставлен целым. Лимит 30 с не увеличен, код продукта не менялся.

Локальная проверка на Windows:

- До правки: `custom-shape` 3/3 на собственном холодном dev-сервере, около 5 с на сценарий; исходный Linux-таймаут здесь не воспроизвёлся.
- После правки: на тёплом dev-сервере `custom-shape` и `inventory` по пять повторов — 15/15; `focus` отдельно пять повторов — 5/5. При запуске нового dev-сервера на другом порту четыре сценария × пять повторов — 20/20, включая первый холодный заход.
- Два полных `CI=1 npm run test:e2e`: первый — 223 passed, 5 skipped, 1 unrelated flaky `coordinate-pair.spec.ts` (прошёл на повторе); второй — 224 passed, 5 skipped, без flaky. Все три теста #46 прошли в обоих полных прогонах.
- `npm test -- --run` — 1624 passed, 1 skipped; `npm run typecheck`, `npm run lint`, `npm run build` — успешно.

Ограничение: загруженный Linux-хост команды в этой сессии недоступен; 5/5 при load 13–21 должны быть повторены там перед merge. `coordinate-pair` не относится к #46 и не менялся в этом пакете; если он повторится, нужна отдельная задача.
