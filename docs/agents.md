# Система агентов

Оркестратор и семь ролей субагентов Claude Code для этого репозитория. Определения —
`.claude/agents/*.md`, протокол оркестратора — `.claude/skills/orchestrate/SKILL.md`
(команда `/orchestrate`). Правила проекта агенты получают из `CLAUDE.md` автоматически,
поэтому в промптах роли — только то, что отличает роль: что видит, что может, что
возвращает.

Зачем так: пять потоков должны каждый день сходиться в одном зелёном `main`
(«Команда и интеграция» в `CLAUDE.md`). Роли повторяют этапы этого конвейера, а не
потоки команды: правила потока уже заданы картой владения
`docs/project-structure.md` и приходят в бриф, дублировать их в семь промптов —
верный способ получить расхождения.

## Роли

| Роль | Когда | Видит и может | Возвращает |
|---|---|---|---|
| оркестратор (главная сессия) | всё рабочее окно | основная копия на `main`, только чтение; заводит worktree, пишет брифы, запускает агентов, `git pull --ff-only` | итог окна: что в `main`, что в работе, что ждёт человека |
| `builder` | один пакет плана | свой worktree; полный набор инструментов; контракты и зависимости не меняет | ветка с MR, отчёт с командами, числами, мутациями, решениями |
| `reviewer` | после каждого builder; для контрактов, формата, модели, `.claude/` обязательно | только diff против `origin/main`, контракты, README модулей; ничего не правит | вердикт `merge` / `доработать` / `человеку` с `файл:строка` |
| `integrator` | после вердикта `merge`, строго по одному | worktree ветки и основная копия; merge `origin/main`, полный прогон, merge MR, `pull --ff-only`, уборка | merge-commit, числа проверок, состояние `main` |
| `qa` | после интеграции UI, перед вехой, на задеплоенном адресе | Playwright на реальном приложении; пишет в `docs/verification/` и `tests/e2e`, `tests/perf` | сценарий проверяющего по шагам с доказательствами, замеры с командами |
| `operator` | после интеграции UI, перед вехой | приложение в браузере в роли руководителя ОПС, проектировщика, инвентаризатора; скриншоты | где сценарий роли не складывается, топ-5 по отдаче в баллах |
| `jury` | перед вехой и сдачей | только артефакты репозитория | оценка 0–3 по шести критериям с доказательствами |
| `scribe` | E02, конец дня, документ разошёлся с кодом | worktree; выполняет команды, которые описывает | README, доска, решения, матрица; список `TBD` |

Модель роли задана в её frontmatter (`model:`), иначе субагент наследует модель
главной сессии. Роли, где важно суждение и качество кода, идут на `opus`: `builder`,
`reviewer`, `operator`, `scribe`, `jury`. Механические роли на `sonnet`: `integrator`,
`qa`. Модель главной сессии на роли не влияет.

Вне конвейера остаются скиллы: `submission-checklist` перед вехой и тегом сдачи,
`humanizer-ru` для текста README. Для UI-фичи действует обязательный skill gate
ниже; это не рекомендация и не замена ручному проходу.

## UI-фича: обязательный skill gate

Полная матрица, условия запуска и формат доказательств находятся в
[`CLAUDE.md`](../CLAUDE.md) и
[`docs/superpowers/specs/2026-09-21-ui-ux-skill-gate-design.md`](superpowers/specs/2026-09-21-ui-ux-skill-gate-design.md).
Роли отвечают за разные части одного gate:

| Роль | Обязательное действие для UI-фичи |
|---|---|
| `builder` | До кода применить `ui-ux-pro-max` и `frontend-design`; после — браузерный путь, снимок, `accessibility-scan`, `accessibility-inspect` и `web-design-guidelines`; записать доказательства в `HANDOFF.md` |
| `qa` | Повторить детерминированный Playwright-сценарий на свежем `main`, проверить артефакты и при изменении существующей страницы запустить `accessibility-diff` при наличии baseline |
| `operator` | Пройти сценарий роли в реальном браузере, проверить визуальную иерархию и сохранить максимум четыре clipped-снимка «после» на пакет |
| `reviewer` | По diff проверить, что gate пройден, снимки/команды существуют, а условные `fix`/`audit`/`trace` применены или явно объяснено, почему они не нужны |
| `integrator` | Не принимать MR без записи о gate; при падении/флейке потребовать `playwright-trace`, при нарушении — `accessibility-fix` с повторной проверкой |

## Конвейер пакета

```
оркестратор: worktree + бриф
   → builder: тест → код → проверки → push с MR
   → reviewer: diff → вердикт
   → (доработать → тот же builder через SendMessage → reviewer)
   → integrator: merge origin/main → полный прогон → merge MR → pull main → уборка
   → qa (UI): сценарий проверяющего на свежем main
веха: operator → jury → submission-checklist → scribe (доска и README)
```

## Что нужно знать, запуская вручную

- Субагент запускается в рабочем каталоге главной сессии, то есть в основной копии.
  Поэтому worktree заводит оркестратор, а путь к нему идёт в бриф; агент сам
  проверяет, что стоит в нужной ветке. Это же правило действует, если участник
  запускает роль напрямую: «Запусти builder на U03 в worktree …».
- Секреты: Stop-хук `check-secrets.sh` видит только текущую копию, поэтому хук
  `SubagentStop` (`check-worktrees.sh`) прогоняет его во всех worktree после каждого
  субагента.
- `reviewer`, `jury`, `operator` не правят файлы: их инструменты — чтение и запуск.
  Временные spec `tests/e2e/_operator-*.spec.ts`, `tests/e2e/_qa-*.spec.ts`
  удаляются после прогона и в commit не попадают.
- Браузерные тесты из worktree запускаются со своим портом (например `DEV_PORT=5174 npm run test:e2e`):
  Playwright больше не подхватывает чужой dev-сервер молча (D-095, D-096).
- В итерациях агент запускает `npm run test:affected -- --base origin/main`: Vitest
  выбирает связанные unit-тесты, а Playwright — e2e-спеки изменённых модулей;
  полный `npm test` / `npm run test:e2e` остаётся финальным gate перед merge.
- Один `integrator` в момент времени. Два merge подряд без синхронизации между ними
  ломают правило «`main` всегда зелёный».
- Другим coding-агентам (Codex и т. п.) те же роли доступны как текст: промпт роли
  можно вставить в задачу вручную; протокол для них — `AGENTS.md`.

## Ограничения, о которых стоит помнить

- Оркестратор не пишет код и не чинит `main` сам: починка — это пакет для builder с
  приоритетом выше всего остального.
- Агенты не ходят к организаторам и не отвечают на блокеры «человек» из `HANDOFF.md`.
- Всё, что меняет контракт, зависимость, `.claude/` или сокращает объём условий,
  агенты выносят человеку, а не решают между собой.
