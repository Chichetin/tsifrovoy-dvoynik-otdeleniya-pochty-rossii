## 01 — [P0] Применять координаты X/Y одной командой без промежуточной коллизии

**Тип:** bug. **Поток:** 2, согласование с 1 при изменении команд. **Оценка:** 0,5–1 человеко-день. **Зависимости:** нет. **Критерий:** 2D, 30%.

### Проблема и воспроизведение

В `src/features/properties/PropertiesPanel.tsx` каждое поле координаты сразу отправляет изменение со старой второй координатой. Конечная позиция может быть допустимой, хотя оба промежуточных положения запрещены физикой.

На `demo/before.json` добавить скамью `eq_54` из `demo/after.json` в `[7.5, 1]`. Цель — `[2.2, 2]`. Изменить только X → `[2.2, 1]` даёт `OBJECT_COLLISION`; изменить сначала Y → `[7.5, 2]` тоже даёт коллизию. Единая команда в `[2.2, 2]` проходит. Дефект подтверждён запуском store; обход уже описан в `tests/e2e/demo.spec.ts`.

### Результат

Пользователь задаёт пару координат и применяет её одним действием. Физика проверяет итоговую позицию; отвергнутая правка не теряет ввод и объясняет причину.

### Приёмка

- [ ] Воспроизводящий тест падает до исправления и проходит после.
- [ ] Описанный перенос выполняется через карточку без обходного клика рядом с целью.
- [ ] Одно undo возвращает `[7.5, 1]`, redo возвращает `[2.2, 2]`.
- [ ] Запрещённая конечная позиция по-прежнему отклоняется; пустой/некорректный ввод не изменяет документ.
- [ ] Сохранённый и повторно открытый файл содержит правильные координаты, ID, атрибуты и связь с зоной.
- [ ] Пройден UI gate из `CLAUDE.md`, команды и артефакты записаны в MR/HANDOFF.

**Где смотреть:** `src/features/properties/PropertiesPanel.tsx`, `src/state/plan-store.ts`, тесты свойств и `tests/e2e/demo.spec.ts`. Не ослаблять правила коллизий ради редактирования полей.

## 02 — [P0] Выдавать свежий ID при повторном применении кандидата ассистента

**Тип:** bug. **Поток:** 4; подключение в `src/app` — 2. **Оценка:** 0,5–1 человеко-день. **Зависимости:** нет. **Критерии:** ассистент 20%, модель 20%.

### Проблема и воспроизведение

Открыть `demo/before.json`, найти место для `ot_queue_terminal` в `z_entrance`, применить допустимый кандидат, удалить добавленный объект, снова запросить место и применить кандидат с тем же ID. Store возвращает `ID_REUSED`.

`src/domain/advice/placement.ts` резервирует ID среди существующих объектов, но не знает retired; `src/app/App.tsx` применяет `candidate.object` напрямую. Store корректно запрещает повторно использовать удалённый ID. Воспроизведено детерминированным запуском `findPlacements` и `createPlanStore`.

### Результат

При добавлении кандидата используется единый механизм выдачи свежего ID с учётом retired. После вставки выделение и ссылки соответствуют реально добавленному объекту.

### Приёмка

- [ ] Цикл «применить → удалить → спросить снова → применить» проходит с новым ID.
- [ ] Ограничение `ID_REUSED` в store сохраняется; существующий объект не перезаписывается.
- [ ] Preview и применение указывают на один выбранный вариант; устаревший ответ не применяется молча.
- [ ] Undo/redo и сохранение/открытие сохраняют правильные объекты, ссылки и атрибуты.
- [ ] Добавлены регрессия и e2e цикла; проверки и применимый UI gate записаны в MR/HANDOFF.

**Где смотреть:** `src/domain/advice/placement.ts`, `src/app/App.tsx`, `src/state/plan-store.ts`, существующая выдача ID в `src/domain/commands`. Общий контракт менять отдельным согласованным MR, если это понадобится.

## 03 — [P0] Проверять связь числа с метрикой и объектом в ответе свободного чата

**Тип:** bug. **Поток:** 4; изменения контрактов — с 1. **Оценка:** 1,5–2,5 человеко-дня. **Зависимости:** нет. **Критерий:** адекватность и объяснимость ассистента, 20%.

### Проблема и воспроизведение

`src/domain/advice/agent-text.ts` собирает общий набор чисел из результатов инструментов и вопроса пользователя. Наличие числа в наборе не подтверждает утверждение о конкретной метрике/зоне.

Для `demo/before.json` вызвать `createAgentToolState`, затем `runAgentTool(state, 'plan_overview', {})`. `checkAgentText('Свободная площадь помещения — 132 м².', agentEvidence(state, [output], query))` возвращает пустой список проблем, хотя 132 — полная площадь, а свободная — 114,73. Если в вопросе есть 99999, ответ с такой площадью тоже принимается. Это проверка валидатора, не наблюдение ошибки живой модели. Структурированные рекомендации имеют отдельную проверку.

### Результат

Показываемые как проверенные факты связаны с метрикой, объектом/зоной, фазой before/after/delta, значением и единицей. Ввод пользователя не служит доказательством. Допустимо строить числовые фразы детерминированно из выбранных моделью проверенных фактов.

### Приёмка

- [ ] Регрессии на «132 как свободная площадь» и «99999 из вопроса» не проходят как проверенные факты.
- [ ] Проверены перестановка значений между зонами, неправильный знак дельты, единица и числа словами.
- [ ] При неверном/непроверяемом ответе показан корректный расчёт с явным fallback, без ложной отметки проверки.
- [ ] Сохранены ID/ссылки, допущения и ограничения; поведение структурированных рекомендаций не сломано.
- [ ] Есть корпус 24 сценариев: 9 размещений (рабочее место/окно/стеллаж × три синтетических плана), 6 комплектований, 3 сравнения, 6 отказов/провокаций; отдельные регрессии на найденные подмены.
- [ ] Автотесты работают без внешнего API; ограниченный live-прогон записывает модель, дату, режим и результаты без ключей.

**Где смотреть:** `src/domain/advice/agent-text.ts`, `agent-tools.ts`, `server/agent.ts`, `src/features/assistant/AgentChat.tsx`, тесты agent/advice. Числа считает код, LLM — только разрешённая условиями; UI-изменения проходят gate из `CLAUDE.md`.

Файлы `/demo/before.json` и `/demo/after.json` уже доступны на сервере. Однако обучение предлагает скачать JSON и затем вручную открыть его через файловый менеджер. У жюри должна быть возможность начать готовый сценарий непосредственно в приложении.

- [ ] Отказ от замены сохраняет правки; HTTP-ошибка/повреждённый JSON дают понятную ошибку и оставляют текущий план целым.

- [ ] Оба плана совпадают с комплектом сдачи, переживают редактирование/сохранение/повторное открытие.

## 05 — [P1] Выбирать исходный файл для сравнения планов «было → стало»

**Тип:** enhancement. **Поток:** 3 + 4; подключение — 2. **Оценка:** 1,5–2 человеко-дня. **Зависимости:** расчёт сравнения уже существует; задача 03 нужна для гарантий свободного текста, но не для детерминированной таблицы. **Критерий:** ассистент, 20%.

### Проблема

Текущее сравнение использует baseline момента открытия документа. Открытие `after.json` заменяет baseline, поэтому выбрать `before.json` исходной версией без замены текущего плана нельзя.

### Результат

Действие «Сравнить с файлом…» выбирает исходный план отдельно от редактируемого документа и показывает изменения объектов, площадей и проверок. База сравнения не подменяет baseline сохранения/dirty и историю undo.

### Приёмка

- [ ] При открытом `after.json` можно выбрать `before.json` и получить добавленную скамью, удалённое табло и перемещённый терминал с названиями и доступными ID.
- [ ] Итог сверяется с `demo/effect.md`: свободная площадь 114,73 → 113,93 м²; 53 → 53 объекта; ошибки/предупреждения 1/2 → 0/0.
- [ ] Загрузка базы не изменяет текущий план, dirty и историю; ошибочный файл сохраняет текущий документ и предыдущую успешную базу.
- [ ] После правки текущего плана сравнение пересчитывается; сброс/замена базы понятны пользователю.
- [ ] Для несвязанных документов (разные ID планов) есть явное предупреждение об ограничениях сопоставления; неподтверждённое соответствие объектов не выдумывается.
- [ ] Числа выдаёт существующий domain-расчёт, а не LLM; unit/e2e и UI gate приложены.

**Где смотреть:** `src/features/assistant/`, `src/app/App.tsx`, `src/domain/advice/`, `src/persistence/`, `src/state/plan-store.ts`. Изменение формата JSON для этой задачи не требуется.
