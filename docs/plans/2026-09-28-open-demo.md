# Issue #4 — прямое открытие демо

Владелец Максим / Codex, `worktree-4-open-demo`. База `ad27bfd`.

Пользовательская задача: начать работу с готовым планом одним выбором, без скачивания и файлового диалога. Источник `/demo/before.json` и `/demo/after.json`, тот же `readPlanFile` и `replaceDocument`, что у локального JSON. Копия плана в компонентах не создаётся.

В первой карточке обучения — две кнопки «Исходный демо-план» / «Изменённый демо-план». Выбор закрывает обучение и запускает загрузку. После закрытия обучения те же варианты доступны из компактного действия «Демо» в файловой группе. Новый пункт должен сохранить одну строку шапки на 1280×800 и 1440×900. Использовать текущие цвета/шрифт/кнопки; не вводить третий визуальный стиль меню.

Состояния: idle → подтверждение замены непустого/изменённого плана → loading → done/error. Отказ подтверждения не запускает запрос. HTTP/JSON ошибка не заменяет документ. Последний запрос выигрывает; смена/правка документа во время ожидания отменяет результат. Отдельная защита отмены/sequence не позволяет старому ответу затереть новую работу.

Финиш: keyboard/focus, loading/error, отказ замены, гонки запросов, обычное сохранение и повторное открытие обоих демо; сравнение с файлами комплекта. Unit/e2e, два целевых viewport, до четырёх снимков с просмотром. Не закрывать Issue #4 по одному helper-тесту.

UI-скиллы из CLAUDE.md (`ui-ux-pro-max`, `frontend-design`, `playwright-interactive`, `webapp-testing`, `playwright`, `accessibility-scan`, `accessibility-inspect`, `web-design-guidelines`) отсутствуют в текущем каталоге скиллов. Fallback — Playwright, live DOM/клавиатура, снимки и ручной просмотр; полный UI gate остаётся ограничением, не объявляется зелёным.

Первый пакет — `demo-plan.ts` и проверки настоящего codec/серверных fixtures, без подключения UI. Дальше общий контроллер открытия источника текста и две точки входа. Формат документа, dirty/baseline/undo и внешние контракты не меняются.
