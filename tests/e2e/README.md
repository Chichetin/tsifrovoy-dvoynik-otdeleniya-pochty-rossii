# tests/e2e

Полный пользовательский сценарий и браузерные спецификации отдельных модулей.

**Владелец:** поток 5. **Пакеты:** Q01.
Это место для реализации; пока здесь размещена только карта модуля.

## Граница модуля

Общий запуск и сквозные specs принадлежат потоку 5. Каждый модульный spec из плана пишет владелец соответствующего пакета; один файл — один владелец.

## Запуск

- `npm run test:e2e` — Playwright сам поднимает dev-сервер на порту из `DEV_PORT`
  (по умолчанию 5173) и не переиспользует чужой (D-095, D-096).
- Из worktree, когда 5173 занят соседом: `DEV_PORT=5174 npm run test:e2e`.
- Прицепиться к уже запущенному `npm run dev` вручную: `PW_REUSE_SERVER=1 npm run test:e2e`
  — только для отладки, порт при этом должен быть свой.
- Браузер — бандловый Chromium из `npx playwright install chromium`. Системный
  браузер включается переменной: `PW_CHANNEL=chrome npm run test:e2e` (D-125).
  В самой спеке `test.use({ channel: … })` не пишется — иначе набор перестаёт
  запускаться по README на машине без Chrome; это проверяет
  `tests/e2e-channel.test.ts`.
- `test` и `expect` спека берёт из `./fixtures`, а не из `@playwright/test`: фикстура
  заранее отмечает мини-обучение пройденным, иначе его модальное окно закрывает
  приложение (D-195). Свой контекст (`browser.newContext()`) — `skipOnboarding(context)`.
  Голый `@playwright/test` берёт только `onboarding.spec.ts`.
- Адрес в spec не пишется руками: страница открывается `page.goto('/')` поверх
  `baseURL`, а ручной запуск браузера берёт `baseURL` из фикстуры (`view3d.spec.ts`).
